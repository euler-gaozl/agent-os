# Agent OS

面向多个业务的可扩展 Agent 基础设施。第一个业务应用是中国期货基本面研究工作台。

## 当前状态

本仓库目前处于架构设计阶段，尚未实现或部署 Runtime、ToolHub、Sandbox 和存储服务。

v0.1 独立静态评审结论为：**修订后可开工，无需推翻职责分层**。没有运行可靠性、性能、模型质量或故障注入测试。开源组件仍是待验证候选，未锁定最终技术栈。

## 设计目标

- Runtime 管理任务、子任务、预算、取消、检查点和恢复。
- ToolHub 管理版本化业务能力；业务规则保留在各自能力包中。
- Skill、提示词与工具支持 Agent 编排；事务、校验和数据一致性由确定性代码保证。
- 上下文是持久化状态的当前工作集，不能成为关键事实的唯一副本。
- 运行状态、证据与产物、业务事实、长期记忆分别管理。
- 沙箱产生暂存结果，正式业务数据通过校验与提交协议写入。
- 逻辑分层不要求拆成多个微服务；从可维护的本地部署开始。

## 技术选型原则

以性能和模块适用性为主要依据，优先评估 Rust、Go、TypeScript，原则上避免 Python，不因开发方便默认采用 Python。模块选型需考虑正确性、延迟、吞吐、内存、部署与维护成本；关键路径以实际工作负载测量。具体语言和开源组件仍待选定，不预先引入多语言复杂度。

## 开工前需要明确的契约

1. 运行状态、事件、检查点和上下文清单的一致提交与恢复协议。
2. 工具调用的并发幂等、结果核对，以及过期 Worker 的提交隔离。
3. Compact 对有效约束、未决问题、冲突和版本的处理规则。
4. 产物发布、新增引用与垃圾回收之间的并发协议。

## 仓库范围

本仓库保存代码、接口契约、架构、验证材料和不含敏感信息的示例配置。个人研究数据库、原始资料、模型与 GitHub 凭证、运行日志和沙箱工作区保存在本地或相应存储服务中，不随仓库上传。

期货业务负责信息收集、校验、按时间分类、事实反馈与留存。预测和交易判断由用户负责。
