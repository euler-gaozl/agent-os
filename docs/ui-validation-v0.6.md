## 实际检查

- 中台六个入口：Agent、ToolHub、知识库、运行记录、服务与实例、模型与凭证。Agent 编辑五个配置页、右侧试运行区均可访问。发布状态筛选限定当前页，目录搜索、无结果、连接异常和加载中分别呈现。
- 真实知识库检索受控验收材料，显示原文库存 105、初值 120、差值 -15 和计划 20；这是假设材料，不是期货事实。运行详情可回读既有 DSH 结果和 Markdown 表格。
- 独立研序首页、历史搜索、原有公开资料任务的结果阅读；桌面与 390px 窄屏。中台六页、Agent 五个配置页、研序首页/结果页均无整页横向溢出，宽表在内容区滚动。
- 检测弹窗从原先超出视口改为有界滚动，39 条审计记录默认折叠。实际操作 Tab、Shift+Tab、Escape、关闭后的焦点恢复；窄屏导航可开关。
- 真实中台将独立验收 Skill `delivery-reference-check` 从 v1 保存为 v2，保持相同内容。新版本未启用，原绑定仍为旧版；新版本仍包含 `SKILL.md` 和 `references/check.txt`，浏览器回读标记 `SKILL-REF-284` 成功。没有改业务 Skill 或重新执行模型任务。

## 独立评审发现与修复

同一名先前受用户委托的评估 agent 完成只读源码复核，未自行运行浏览器或测试。首轮发现五项问题：全局 DeepSeek 凭证误阻其他模型、Agent 详情乱序导致标题与草稿不一致、知识库跨库回包污染、编辑 Skill 丢附件、ToolHub 新版标题沿用旧版审阅。第二轮发现保存后旧目录刷新、慢文件轮询持续丢弃回包。上述代码修复经其再次静态复核成立；运行证据由以下测试提供，不能把静态复核称为运行测试。

## 受控延迟浏览器回归

`node scripts/ui-race-fixture.mjs` 在回环端口 8109 提供真实 Console 构建所需的隔离 HTTP 夹具，不连接用户数据库、模型、凭证或外网。A 请求延迟 12 秒，B 延迟 20ms。构建 Web 后可重复以下手工场景：

1. Agent 列表依次点击 A、B；A 回来后标题、名称、唯一标识与提示词仍属于 B。实测通过。
2. 保存 B，立即切 ToolHub；保存回包后仍显示 Skill 目录，不重新打开编辑器。实测通过。
3. A 库发起检索后返回列表并打开 B，再检索 B；A 文件/检索回包晚到后仍只显示 B 的文件和证据。实测通过。
4. 留在 A 库等待 12 秒文件接口；列表显示 `A-only.txt`，不会被每五秒的新请求持续作废。实测通过。
5. ToolHub 检测弹窗先读 a.md、后读 b.md；12 秒后预览仍为 B。填 v1 审阅原因，点击夹具的重新检测按钮模拟目录新版本，下一轮目录刷新关闭旧弹窗；再打开 v2，原因、预览为空，启用按钮禁用。实测通过。首次等待 UI 隐藏的工具调用提前超时，随后目录实际刷新后状态符合预期；未将首次等待超时写成产品成功。

夹具仅验证页面异步状态，不代替 ToolHub 后台行为。真实 PostgreSQL 的 `TestHTTPBaselineEditPreservesBundleAndRequiresFreshApproval` 另外验证附件按指定旧版本复制、旧版不变、新版重新审批、无效基线/跨 ID/损坏附件拒绝。全量 Go 测试与 vet、Web 类型检查/双入口构建、四项 Web 渲染和资源详情测试通过。本轮没有重跑收费模型任务；之前的真实模型证据保留在交付账本。

尚不据此宣称所有浏览器/辅助技术组合已验收，也不把 UI 完成代替独立部署、容量和物理节点高可用验收。
