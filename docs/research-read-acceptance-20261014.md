# 资料读取失败定位与修复

整体单机目标仍未完成。本文只记录真实采集后的两次研究执行、读取修复及其证据，不以服务就绪替代研究质量验收。

## 已完成的资料留存

正式 Sources 通过可恢复配置事务增加四个精确来源主机；74 项配置检查通过。七份网页已由正式 Sources 留存，并由 Knowledge 导入；原始/正文哈希及重复导入身份一致。一个候选地址实际返回 404，失败记录保留，另寻可访问转载后创建新采集身份。网址发现由 Codex 辅助完成，不能宣称 Agent 自主全网搜索。

来源核对保留了 AI 生成摘要与被截断正文的区别、同一时期不同进口报数的冲突、转载并非独立调查等限制。入库成功只证明留存，不能证明内容真实或研究完整。

之前的原生模型及 Futures 发布状态已完成一次新备份的实际隔离恢复：44 个关系/序列指纹、结构权限、10 个账号、3 条凭证解密、6 份档案、25 个发布引用和 3038 文件通过。该备份早于此次七份新资料及后续研究，不能代表最新全量状态已恢复。

## 两次真实执行

1. Agent revision 16：12 次模型请求、24 次工具调用，22 次 `document_read` 覆盖十份资料、无重复窗口；每轮只读两页，后续继续读取无关导航，下一次模型请求因预算耗尽被拒绝。计量 369335 token，未知用量 0，无成稿。
2. 修正任务误用 `knowledge_search` 查询知识库的问题，改为 `kb_search`；新 Skill revision 6 指导每轮 4–8 个独立读取、辨别正文/导航并预留成稿步骤。Agent revision 17 保留原问题、资料、执行器和 12 次请求。首次提交因新 Skill 尚未启用被拒，检测健康后显式启用再以原幂等键提交；没有重复任务。前三轮批量读到十份资料，第4轮把来源原始字节的哈希传给 `artifact_read`，收到服务拒绝而失败。4 次模型请求计量 86191 token，未知用量 0，无成稿。

不靠提高预算或再次从头提交隐藏失败。后续修复后优先恢复同一个失败任务，复用已提交模型与工具回执。没有将这些调用算成研究验收通过。

## 修复与检查

- Knowledge：本地检索增加与导入文档同一坐标的 Unicode 偏移。按冻结分块配置和序号计算，再核对实际片段；重复段落不会指向另一个统计期，无法确认则省略。保留原文、原分块、权限和检索边界，无 schema 迁移。
- Storage：仅对实际不可见/不存在产物或越界页返回明确的 `isError` 业务读取结果，给模型纠正机会；引用继承未发生。哈希损坏为服务错误，普通 HTTP 404/416、鉴权和传输错误不能冒充确定反馈。
- Runtime：生产代码不变。既有事务已经能持久化并重放明确 JSON 结果；新增检查证明拒绝回执复用、新操作纠正、旧 fence 拒绝，以及普通 HTTP/权限/未知效果/服务错误不被吞掉。

独立评审发现首次文本匹配位置及按 HTTP 状态码推断业务拒绝两处问题，均已修正。实际测试：Knowledge 57 项、Storage 5 项、Runtime 17 项通过，三个仓库 vet/独立构建通过。Knowledge 五项外部 RAG、旧 Indexer 二进制和子进程助手未执行，保留为未验；新定位、局部查询计划及 HTTP/回执测试已实际执行。第一轮失败记录未覆盖。

证据入口：`ops/research-intake.path`（采集、原失败、reading-repair）、`ops/research-read-repairs.path`（代码检查）、`ops/native-recovery.path`（此前实际恢复）。完整资料、模型输出和配置仅在本机。

当前修复通过本机检查，尚待受管安装与原任务恢复核验。GitHub Actions 保持禁用；无最终 CI、完整页面或整体交付完成的声明。
