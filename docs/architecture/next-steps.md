# 评审整改与验收清单

来源：[v0.1 独立评审](agent-os-v0.1-independent-review.txt)。本文为工作清单，不表示整改已经完成。

## 先定契约

- [ ] 运行一致性：选择事务化状态或事件历史为权威，定义 run_revision、提交序号、检查点、恢复指针和持久化派发。
- [ ] 调用一致性：定义 operation_id、attempt_id、参数绑定、事务去重、fencing 和 UNKNOWN 核对。
- [ ] 上下文有效性：定义有效约束、未决问题、冲突和替代关系，区分恢复、历史回放与使用最新数据重跑。
- [ ] 产物生命周期：定义不可变发布、内容哈希、引用关系、删除状态、租约和 GC 并发规则。

## 按模块细化

- [ ] 模型调用：请求与尝试状态机、实际请求清单、断流、结果选定、用量与潜在重复费用。
- [ ] 子任务与取消：先登记再启动、父子生命周期、预算、在途效果、取消和补偿的边界。
- [ ] 物理存储：明确支持的故障域、持久性、空间不足、备份范围、RPO/RTO 和恢复核验。
- [ ] 组件选型：用职责映射排除多个框架同时拥有状态、重试或 Compact 的情况。
- [ ] 性能与语言选型：定义首版工作负载、延迟/吞吐/内存预算，按模块评估 Rust、Go、TypeScript；原则上避免 Python，不以开发方便作为默认采用理由，重新核对开源候选的语言和运行依赖。

## 最小验收场景

以下场景全部尚未执行。

- [ ] 在任务提交、调用意图、业务提交与运行检查点之间强制终止 Worker，确认恢复边界。
- [ ] 重复派发与旧 Worker 复活，确认无重复效果且旧提交被拒绝。
- [ ] 模型断流、延迟旧结果、重试与工具升级，确认输出和版本一致性。
- [ ] 多次 Compact 后清空进程内状态，检查用户纠正、口径变化和来源冲突仍可正确使用。
- [ ] 在 GC 与新增引用、产物晋升之间制造竞争，检查证据链和不可变性。
- [ ] 父子任务取消、接管与重复启动，检查预算、提交和状态归属。
- [ ] 磁盘满、对象缺失、备份恢复和观测系统不可用，检查持久性及失败反馈。

每项结果应附输入与代码版本、故障位置、提交记录、执行次数、恢复结果，以及未覆盖的情况。
