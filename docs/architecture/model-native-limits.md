# 输入输出使用模型原生能力

2026-10-14，用户要求取消输入/输出的人为上限。纳入现有单机目标，不另建或缩小目标。

## 已核实

官方[模型列表](https://api-docs.deepseek.com/api/list-models/)及本机实际GET `/models` 均返回
Flash总窗口1048576、最大输出393216。脱敏返回保存在budget-activation证据目录的
deepseek-model-metadata.json；没有凭证。官方[请求协议](https://api-docs.deepseek.com/api/create-chat-completion/)
说明输入/输出共享窗口；不传max_tokens会采用供应商默认值，不代表无限输出。
当前v3/SDK仍有32768验证上限，业务配置为64K/6144；新要求尚未部署。

## 实施与验收顺序

1. 从可信供应商配置解析能力，保存来源/时间/版本，冻结进Agent/任务快照；恢复时不实时查询或暗改旧任务。缺少能力的模型要求管理员补充，不默默使用32K/4096。
2. 中台默认使用模型支持范围，取消默认输入/输出小额度；业务端不展示基础设施参数。旧显式配置仅供旧任务，新Agent版本采用新策略。
3. 新固定Harness沿用DSH循环及落盘/压缩协议。最终完整请求按物理窗口及最大输出处理；长输入先持久化再压缩/引用回查，不静默裁剪。摘要固定2048上限也需处理，不能只改生成。
4. SDK、Registry、Runtime、Worker、Console和发布兼容一起支持新协议，旧v1/v2/v3字节及回执不改。核对最终序列化后的工具/约束占用。
5. 总成本/调用次数与长度分开。旧250000总token预算无法预留393216最大输出，不能保留这种隐性拒绝后声称取消上限；明确成本保护，保留计量、未知调用保守记录及有限异常重试。真实测试继续小额有界。
6. 传输/内存队列、权限、并发和超时保护保留；验证其能容纳模型范围。验收能力解析和快照、长输入/输出、压缩、旧引擎恢复、新协议强杀接管、中台配置与实际请求一致，最后小额官方验证。
