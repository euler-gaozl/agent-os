# v0.3 服务与执行契约

日期：2026-10-11。本文描述代码现状；v0.1 图和独立评审不覆盖本版实现质量。

## 分层与职责

能力中台配置资源，自定义 Agent 绑定资源的确定版本；业务应用调用发布的业务动作。一个动作把用户输入、固定研究说明、约束和 Agent 版本组合为 Runtime 任务。不同业务可以复用底层服务，无须复制 Agent 编排。业务用户不需要理解 Skill 或 MCP。

| 独立进程 | 默认端口 | 职责与主要接口 |
| --- | --- | --- |
| control | 8090 | 中台静态资源、认证、`/api/*` 转发和实例状态 |
| registry | 8096 | `/v1/resources`、凭证写入、MCP 工具发现 |
| runtime | 8094 | `/v1/runs`、事件/调用记录、取消、约束修订、恢复和未知效果核对 |
| worker | 无 | 从持久化队列领取执行；模型及工具编排；每进程一个在执行任务 |
| toolhub | 8091 | `/invoke`；参数校验、工具版本快照、回执与业务效果 |
| storage | 8092 | documents、artifacts、手动 GC |
| knowledge | 8095 | `/v1/upload`、query、retrieve、files、导入核对 |
| indexer | 无 | 扫描待索引文件，独占单文件的索引操作 |
| sandbox | 8093 | `/execute`；调用受限 Docker 容器，绝不在宿主机回退执行 |
| futures | 8098 | 独立静态应用与 `/api/actions`、`/api/tasks`、readiness |
| telemetry | 无 | 可选异步导出已提交事件；失败不阻塞任务 |

首版使用一个 Go 模块和镜像，以角色启动独立服务。HTTP 调用已隔离中台配置、业务提交、Runtime、工具和知识检索，但各角色仍使用共享的 Store 与 PostgreSQL schema。ToolHub 本地效果需要和执行回执同事务，业务列表也直接读取共享库。因此这是可分别启动/扩容的服务拆分，不是严格独立数据所有权或任意跨版本滚动升级承诺。下一步拆库必须引入明确的 outbox/收件回执契约，不能简单把事务切成两个远程调用。

## 运行状态权威

`runs` 的事务化当前状态是恢复权威，`events` 是同事务审计记录；不存在另一套框架重试器或内存队列作为权威。领取任务使用 `FOR UPDATE SKIP LOCKED`，数据库时钟租约，领取时递增 fence。默认租约 20 秒，心跳约 6.7 秒，空闲轮询 300 毫秒。

提交需要匹配 run id、owner、fence、有效租约和约束版本；在锁住 run 行后校验，再提交效果和回执。旧 Worker 恢复后不能通过旧 fence 发布本地正式结果。API 响应成功之前，任务和幂等键已经提交。UI 重连读取已提交事件与检查点，不宣称模型生成能够断点续传。

状态包括 queued、running、waiting_children、waiting_unknown、completed、failed、cancelled。进程中断留下可接管租约；业务失败需要显式恢复。恢复同一次执行保留资源快照；重新提交任务才会采用新选定资源版本。当前没有完整历史确定性回放引擎。

## 模型与工具调用

提交时展开 Agent 绑定的资源版本，保存 prompt、Skill、MCP schema、子 Agent 和知识配置快照。模型实际请求、尝试和结果存入数据库；选定输出先持久化，再执行工具。模型 HTTP 使用非流式 `/chat/completions`。截断输出或半段 JSON 不能推动工具。请求重试记为新 attempt；已完成结果可回读，失联请求可能产生重复费用。

稳定 operation id 绑定参数哈希，不能用同一 id 更换输入。数据库内工具的业务写入与完成回执同事务。外部写操作中断/回执不明时进入 unknown，等待带证据的核对；不保证外部 exactly-once。只有完整工具名匹配并声明只读的 MCP 调用可以安全重发。把某个 Connector 标为只读是管理员的责任，不能依赖模型自称只读。

MCP 适配固定协议 `2025-11-25`，支持 Streamable HTTP 初始化、工具发现、调用与 SSE 响应；不支持 stdio 安装包、任意旧协议或本机脚本自动运行。Skill 导入是指令文本/结构化资源，尚无带脚本、依赖和签名的完整 Skill bundle 安装机制。工具 schema 与配置可冻结；Go 实现代码和供应商模型别名没有自动按 run 固定版本，跨部署恢复要保留兼容性。

## 子任务、约束和取消

子 Agent 先登记后执行，用 spawn operation id 去重；绑定深度最多 2，每个 Agent 子任务额度最高 8。父任务等待子结果，取消和约束修订按父先于子的锁顺序作用于任务树。等待核对的子任务未结束时，父任务不能显示“取消完成”。取消不能撤回已经发生的外部效果。

约束记录独立于模型摘要，rule_revision 变化后拒绝旧计划的新效果，要求下一安全边界重新考虑。当前额度是步骤/子任务数量，不是美元费用上限或跨父子树严格 token 预留。

## 什么放上下文，什么落盘

| 数据 | 持久化时点 | 放入模型上下文的方式 |
| --- | --- | --- |
| 用户任务、约束、Agent 版本 | 接受任务的事务内 | 每轮固定加载当前有效约束和固定资源 |
| 实际模型请求与 attempt | 发出请求前 | 可回查记录，不全量永久塞入上下文 |
| 选定模型结果 | 工具执行前 | 当前工作集中的 assistant 消息 |
| 工具意图、正式效果与回执 | 意图先落盘；本地效果与回执一起提交 | 只加入已确认工具结果 |
| 上传原文件、正文、来源、分片 | 接受上传时；远程索引随后执行 | 按绑定库检索；结果附文档和来源 |
| Compact 前完整消息 | 压缩前发布内容哈希产物 | 摘要 + 原记录引用 + 最新完整工具轮次 |
| 记忆 | 显式 note_save | 按 scope、有效期与 supersedes 筛选，再按需回读 |

上下文预算按请求 UTF-8 字节（含 tool schema）估算，并非供应商准确 token 数。固定部分超过预算一半时显式报错；无法安全压缩也报错，不静默丢必需约束。摘要仍由模型生成，虽然原文可回查，仍可能遗漏语义。没有真实长任务 Compact 质量分数。口径冲突/未决问题目前靠文档元数据、提示词与摘要保留；尚无独立、强制重注入的结构化矛盾账本。

## 产物、索引与回收

原文件采用 SHA-256 + PostgreSQL bytea，不可变，单个 artifact 上限 4 MiB；上传入口单文件 1 MiB。正文与来源单独保留。索引是派生数据，不能覆盖原始证据。Milvus 命中必须反查本库的稳定 chunk id，不能返回其他库 chunk。LightRAG 为每个知识库版本要求专用 endpoint/workspace，避免旧 Agent 读到新库图谱。

上传文件按库版本和原文件哈希去重。修改 Embedding 或知识配置产生新版本和新索引，须重新导入；旧 Agent 继续读取原版本。LightRAG 接受上传不等于处理完成，要取得 track id 并轮询处理状态。丢失回执进入 unknown，需要从外部服务核实；不能自动重新上传。

引用与 artifact 处于同库事务边界。GC 只手动运行，删除无引用且超过 24 小时的对象；没有自动退休运行记录/资料引用根，也没有自动删除长期知识。当前可能一直保留有引用资料，这是明确的保守策略，不宣称自动冷热分层。模型摘要过期和远端索引清理还没有完整生命周期管理。

## 部署与故障边界

已验证 Worker 进程故障恢复、真实 PostgreSQL 事务和一次隔离数据库备份恢复。没有验证磁盘损坏/写满、断电、跨机故障、数据库主从切换或 RPO/RTO。pg_dump 包含原文件与其引用，外部 Milvus/LightRAG 索引不在备份内；MASTER_KEY 需另行保管。

本地 DEV_LOCAL 只允许回环入口与严格 Origin/Host/header 校验。服务间共享 token；生产/Compose 使用独立 admin/business token，但没有多租户 RBAC。Docker socket 仅给 sandbox broker；它具有宿主 Docker 管理权限，需专用 daemon，所有 sandbox 副本必须指向同一个 daemon。当前沙箱只返回有限日志，不支持文件挂载、任意语言依赖或正式文件发布。
