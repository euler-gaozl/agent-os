# 生产化实施与验收账本

用户约束：Linux 平台常驻预算 2 核 / 4 GB（不含自托管模型、Milvus、LightRAG、Embedding）；知识库目标 100 万份文档 / 1000 万分块。以上是验收目标，不是当前已证实能力。

## 工作顺序

1. 合并已经通过检查的 v0.4 基线，后续变更走独立 PR。（已完成，main=15a7691）
2. 拆分服务实现、构建入口、镜像和服务生命周期；中台与业务 BFF 不直接访问平台数据库。
3. 明确数据所有权和权限，移除跨域 SQL；保留执行效果与回执的原子性，不能通过简单拆库破坏恢复协议。
4. 知识库改为有界上传/索引、持久化队列、增量处理、分页、索引检索；修复全文扫描和任务饥饿。
5. 服务统一超时、背压、连接池预算、优雅退出、错误分类、结构化日志与指标。
6. 独立部署/重启、权限拒绝、断连/中断恢复、真实服务契约测试。
7. 2 核 / 4 GB Linux 下测量常驻和运行资源；百万文档/千万块容量测量单独记录数据分布、存储、冷/热缓存、并发和 P95。
8. 真实 MCP / Milvus / LightRAG / Embedding / 模型供应商联调；缺少凭证或部署环境的项目保持未验收。

## 验收纪律

- 不能把包/目录拆分称为服务解耦完成，不能把接口夹具称为真实服务联调。
- 所有测试标注实际样本量；不把小规模测试外推为千万块容量证明。
- 平台预算与检索后端预算分开；容量还需磁盘预算。1024 维 float32 的 1000 万向量约 40.96 GB，不包含索引、原文、副本和备份。
- 本机 Windows 当前无可用 WSL / Docker；Linux 容器验证优先使用 GitHub Actions，不修改用户系统虚拟化或自动重启电脑。
- 历史资料及运行恢复需要迁移和备份证据；不能以清库或重建模拟数据代替迁移。
